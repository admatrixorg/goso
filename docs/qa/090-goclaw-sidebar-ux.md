# QA — SPEC 090 GoClaw sidebar UX audit

Date: 2026-08-29. Scope: docs-only, clean-room behavior study. No GoClaw or ZaloCRM source was read or copied, no product state was changed, and no credential value was captured in this document.

## Method and mapping baseline

- Logged into the live Dewee dashboard at `127.0.0.1:18791` with the gateway-token form and opened every one of the 32 left-navigation routes under CORE, CONVERSATIONS, CONNECTIVITY, CAPABILITIES, DATA, MONITORING, and SYSTEM. Create/configure surfaces were opened only to inspect fields and contracts; no create, save, install, approve, revoke, import, restore, or delete action was submitted.
- Glanced the live goso Control Plane at `127.0.0.1:3000`. Its visible live navigation agrees with the source inventory in [App.tsx](../../control-plane/src/App.tsx#L86): Overview, Heatmap, Agents, Sessions, Chat, Marketing, Teams, Vault, Memory, Connectors, Functions, Events, Providers, Channels, Webhooks, Traces, and Settings. The rendered page bindings are in [App.tsx](../../control-plane/src/App.tsx#L449).
- Mapping terms: **PARTIAL** means a named live goso page exists but does not yet cover the observed operator contract. **THIẾU** means the live Control Plane has no corresponding page. A related demo-only component does not count as a live mapping.
- Credential assessment is deliberately literal. “Never-return” is claimed only when the UI stated it or the goso source shape omits the secret from reads. A blank credential input by itself is not proof of a safe GET contract.

## Executive findings

Dewee organizes the operator journey around gateway operations: health first, then conversations, connectivity, capabilities, data, monitoring, and system administration. Goso already has credible foundations for Chat/Sessions, Agents, Channels, Providers, Functions, Teams, Vault, Memory, Webhooks, Traces, and Settings, but only Chat/Sessions approaches the benchmark's operator flow; most other matches are partial and 15 Dewee surfaces have no dedicated corresponding page in live navigation.

The strongest reusable credential contract observed was the Channel dialog's explicit “encrypted server-side; never returned in API responses” message. Dewee also masks gateway API keys in lists and shows only “API key set” for configured providers. MCP environment values, TTS keys, provider keys, and S3 secrets expose input surfaces without an equally explicit read/write contract; goso should standardize all secret editors on write-only input, boolean/prefix status on GET, deliberate rotate/clear actions, and no secret hydration.

## CTO acceptance rules for follow-up UI

1. Preserve goso's product model and codebase; behavior findings are inputs, not a license to copy layouts, wording, source, or data.
2. Every secret editor must render an empty write-only field on load, return only `*_set`/masked prefix metadata, support an explicit clear/rotate path, and never put secrets in logs, traces, exports, browser screenshots, or error bodies.
3. Every operator page needs first-class loading, empty, actionable error, permission-denied, and stale/retry states. “Blank panel” is not an acceptable state.
4. Destructive actions require target naming and confirmation. Approval/revoke/restore/import/delete actions must be audit logged.
5. Live-stream pages need pause/resume, bounded retention, redaction, reconnect/backoff, and a visible connection-state indicator.
6. Keep the high-priority goso pages stable while filling gaps in the locked queue: Overview, Chat/Sessions, Agents, Channels, Providers, Functions, Teams, Vault, Memory, Webhooks, Traces, Settings.
