## Security and secret conclusions

- **Admin token:** current code is default-closed. Empty admin/view tokens without explicit dev mode produce 401; this was live-proved on protected endpoints. The old market-readiness statement that empty means pass-through is stale. Explicit dev mode remains a deliberate bypass and needs a production startup guard.
- **Master key:** AES-256-GCM with a random nonce is real; empty/invalid key refuses persistence. The operational gap is compose propagation and key lifecycle, not the primitive.
- **Provider/channel GET:** public provider structs contain name/type/base URL/model/key-set/source only. Channel catalog exposes the environment variable name and configured boolean only. Tests assert no token/key value in GET. Live GET could not be authenticated in this audit, so code/test evidence is not represented as live response evidence.
- **Webhook hashing:** Bearer webhook tokens are SHA-256 hashed and compared in constant time; HMAC-SHA256 is real. Persistence, tenant scope, freshness/replay, and useful async completion remain open.
- **Tracked secrets:** no product API key, master key, or production admin credential was found. The known local placeholder in `.env.example` should not be mistaken for a product credential, though production should never reuse it.

## Non-findings / intentionally parked

- Agent/session delete, session rename, and agent display-name PATCH are absent because there is no owning HTTP contract; the UI correctly does not invent them.
- Channel token configuration is env-only by SPEC 063 and remains a decision/next-spec item. An env name in GET is metadata, not a leaked value.
- Production channel credentials/protocol choices remain DI-01…07. Adapter fixture coverage is not claimed as live Telegram/Discord/Slack/Feishu/WhatsApp/Zalo parity.
- PostgreSQL/pgvector, sandbox image, headless browser, media vendors, Tailscale, Redis, Apple signing/update, Stripe, K8s, and Grafana SaaS remain explicitly parked/CẮT under DI-09 and DI-11…18/21.
- DEMO Home/Tasks/Meetings/Friends/Calendar/Gallery are intentionally mock and badge-marked. They were not scored as durable CRM data.
- The live model contract in code is router9 defaulting to `ocg/deepseek-v4-flash`. No authenticated chat was run, so this report does not claim a successful completion, tool call, or stream from that model.

## CTO release decision

Do not market this as production-ready or full GoClaw parity. It is a credible clean-room internal platform/demo with green unit/type checks and a broad admin UI, but CTO-01, CTO-02, CTO-04, and CTO-07 should block a production pilot. Recommended order: SPEC 066 runtime routing + production security/compose, SPEC 067 durable webhooks, SPEC 068 true streaming, then DI-09-backed tenancy/semantic work and SPEC 070 recovery operations.
