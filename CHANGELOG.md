### Added

- SPEC 184: Per-tenant skill directory. Shared skills stay at `GOSO_SKILLS_DIR/<name>/SKILL.md` and only the `default` tenant may create or delete them. Other tenants read that root and store their own skills at `<dir>/t/<tenant>/<name>/SKILL.md`; the tenant file wins on a name clash. `t` is not a skill name. Tenant paths reject `..`, slashes, and symlinks. Create is a temp file, fsync, and rename. `GET`/`POST`/`DELETE /api/skills` follow the request tenant. `use_skill` and `skill_search` follow `agent.TenantID`, or `default` when there is no agent. Import/export catalog, export, import, and rollback use the same paths. BM25 is one index per tenant, not one global index. SPEC 175 `--apply` stays refused. No control-plane change.
- SPEC 180: GoClaw `memory_documents` import from a JSONL file (no live database, no schema change, no pgvector). `--tenant` is required. A local denylist is required (`--deny-file` or `GOSO_TENANT_DENYLIST`); a missing, empty, or malformed file stops before any work, and a listed tenant stops before any write. The report's `denied` field is a count and does not name the tenants. Empty `user_id` on `memory/` or a root file is written with `PutTenantAt` at `memory/goclaw/<agent>/<path>`. An agent slug containing `..` is rejected. A non-empty `user_id` becomes a durable memory whose body starts with the source path, on an archived session `gc-docsess:…`, id `gc-doc:<agent>:…`. `customer_key` comes from the contacts importer TSV (`channel`, `sender`, `user`, `key`). Channel names are normalized to the live catalog (`zalo_personal` → `zalo-personal`, `lark` → `feishu`) before the key is stored. No map row falls back to `goclaw:<user_id>`, never empty. A target that already exists and differs is `native-exists` and is not updated. `_system/` names go to `--system-names-out` (mode 0600), not stdout. `memory_chunks` are not imported. `--remove-tenant` deletes only `gc-doc:`, `gc-docsess:`, and `gc-vdoc:` rows. QA `docs/qa/180-goclaw-memory-documents/`.
- SPEC 182: Customer-scoped knowledge graph. `kg_entities` and `kg_relations` gain `customer_key TEXT NOT NULL DEFAULT ''` on the in-memory store, SQLite, and Postgres. The migration is add-only (no update or delete of existing rows). Channel writes stamp the key from the session label, the same rule as memories; web writes stay `''`. KG search, neighbour expand/relations/graph, `memory_search` / `memory_expand`, and the KG HTTP reads filter `customer_key='' OR customer_key=<current customer>` for a channel caller. Web chat stays unscoped. `RecallMemories` is unchanged. Postgres indexes `idx_kg_entities_customer` `(tenant_id, agent_id, customer_key)` and `idx_kg_relations_customer` `(tenant_id, customer_key)` are `CREATE INDEX CONCURRENTLY` in `docs/qa/182-kg-customer-scope/migration.sql` and are not created at startup. Prod index build waits for Dat's approval. QA `docs/qa/182-kg-customer-scope/`.
- SPEC 171: `GOSO_VAULT_DOCLING` defaults off. While it is off, uploaded jobs stay `uploaded` and the sidecar is not called. While it is on, the gateway claims `uploaded` pdf, office, and image jobs, calls an internal Docling sidecar over HTTP, and writes markdown only through `PutTenantAt` at `sources/inbox/<job id>.md` (or `-partNN.md` when the markdown is over 1 MiB). OCR in this PR is Tesseract CLI `vie`+`eng` only. txt and md are normalized to UTF-8, NFC, and LF in the gateway and are not sent to OCR. A result with no letters fails as `empty_conversion` and the raw file is kept. A missing sidecar fails the job as `not_configured` and does not take down the HTTP server. Per-page timeout defaults to 60s with 2 attempts; those numbers are not VPS2 measurements. Additive columns on `vault_ingest_jobs`: `source_paths`, `ocr_engine`, `ocr_lang`, `page_count`, `converted_at`. `GET /api/vault/ingest/{id}` returns them and still hides another tenant. SPEC 172, 173, and 174 hooks are no-ops, so a finished job stays `converted`. The compose sidecar is profile `docling`, non-root, capped at 1 CPU and 2 GiB for dev, and attached only to an internal network. `go test` uses a fake converter and does not dial Docling. A second upload of a converted file is a duplicate; a failed conversion can be retried without writing `raw/` again. QA `docs/qa/171-docling-converter/`.

- SPEC 154 follow-up (issue 43): Postgres recall step 2 (the OR) no longer leaves the plan to the row estimate. A small customer is read through `idx_memories_customer` and a small agent through `idx_memories_session`. Otherwise a 128-row sample of `idx_memories_tenant_created` decides the window: a scoped match still reads the full newest window, and zero matches go to the bitmap without scanning the rest of that window. A bounded newest-first window on `idx_memories_tenant_created` is used when it already holds the limit. When that window belongs to another agent, `agent-window` reads the requested agent's newest rows through `idx_memories_session` and stops at the limit. The sparse bitmap keeps the agent (`session_id IN` that agent's sessions) and the customer inside the CTE, so other agents and customers are not materialized. A large customer whose newest window already holds the limit (`customer-window`) uses `idx_memories_customer_created` on `(tenant_id, customer_key, created_at DESC)` and stops at the limit. A short window falls through to `bitmap-and-customer`, which keeps `customer_key` in the bitmap. Rollback adds `DROP INDEX IF EXISTS idx_memories_customer_created`. CI checks the path, the index, and a row/buffer ceiling; the 50 ms samples run only when `GOSO_RECALL_BENCH=1`. The candidate cap stays 2000. There is still no `ts_rank` in SQL. Ordering and the AND-then-OR candidate set are unchanged. QA `docs/qa/43-recall-or-stable-plan/`.
- SPEC 154: Postgres recall and search use a generated `body_tsv` column (`to_tsvector('simple', body)`) and a GIN index on `memories`, `vault_docs`, and `kg_entities`. Existing columns are not altered. Recall no longer stops at the newest 500 rows. Postgres loads at most `recallCandidateCap` (2000) rows in two steps, both `ORDER BY created_at DESC`, with no `ts_rank` in SQL: an AND of the query tokens, then an OR only when the AND returned fewer hits than the caller asked for. Go still scores by token overlap. A btree index `idx_memories_tenant_created` on `(tenant_id, created_at DESC)` is added. Body search is a whole word or phrase (`phraseto_tsquery`): `Min` does not find `Minh`. Message text, vault titles, and entity names still use substring match. `SearchMemory` still has no tenant filter. SQLite FTS5 is unchanged. There is no off switch; rollback is a code revert plus `DROP INDEX` on `idx_memories_body_tsv`, `idx_vault_docs_body_tsv`, `idx_kg_entities_body_tsv`, and `idx_memories_tenant_created`. QA `docs/qa/154-postgres-tsvector-gin/`.
